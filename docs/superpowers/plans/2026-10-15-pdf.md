# PDF export and project report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** PDF as a format of the table export, and a tick-box project report.

**Architecture:** `export/pdf.ts` builds PDFs in the browser from plain data (lazy-loading jspdf), `export/download.ts` saves a Blob, `ExportDialog` gets a format switch, `ReportDialog` + a menu item on the project page fetch only the ticked sections.

**Tech Stack:** jspdf 4.2.1, jspdf-autotable 5.0.8, React 19, MUI, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-15-pdf-design.md`

## Global Constraints

- Before this plan: frontend 609 tests (58 files), 98.25%/97.4%; backend 278; e2e 73+12. Run each task's tests before and after.
- No money, cost or history in a PDF that the screen would not show to that person. No new API. CSP unchanged. Targets 44 px. Axe clean.
- Commits signed off with the Claude trailer; never push.

## Review Focus

1. Text outside the PDF font's range is replaced, never garbled; long names wrap instead of running off the page.
2. The report asks the server only for the ticked sections, and a 403/404 on one section does not lose the others (it says which section failed).
3. Money sections cannot be ticked when the person may not see money; History only for admin and the project's manager.
4. A very long table (100+ rows) paginates with the header repeated and correct "page n of m".
5. A failed or slow PDF build leaves the dialog usable (button re-enabled, message shown), and no file is saved.
