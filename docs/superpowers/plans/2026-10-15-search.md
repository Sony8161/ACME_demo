# Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** one always-visible search box that finds projects, people and tasks within what the person may see.

**Architecture:** a small `search` domain on the backend (router, service, schemas) that reuses the project and user queries and adds one task query; a `GlobalSearch` combobox in the app bar.

**Tech Stack:** FastAPI + psycopg + pytest (real DB), React 19 + MUI + Vitest, Playwright/axe, Postman collection generator.

**Spec:** `docs/superpowers/specs/2026-10-15-search-design.md`

## Global Constraints

- Before this plan: backend 278 tests, 97.5%; frontend 636 tests (61 files); e2e 80 + 12. Run each task's tests before and after.
- Scoping is enforced on the server, never by the screen. No money or salary in results. snake_case JSON. Targets 44 px. Axe clean.
- Commits signed off with the Claude trailer; never push.

## Review Focus

1. An employee must not learn another person's name, a project they do not work on, or someone else's task from a search.
2. A manager must not find another manager's project or its tasks, nor an admin.
3. `%`, `_`, quotes and very long text in `q` do not break the query or match everything.
4. Fast typing: an older, slower answer must never overwrite a newer one.
5. The list is usable by keyboard and a screen reader (combobox, listbox, active option).
